## 1. User Story Statement

**As a** BAHA Demo Operator  
**I want to** theo dõi một bảng điều khiển (Dashboard) tối giản hiển thị tổng quan trạng thái kết nối, tài khoản, trang đại diện, và kết quả phiên tạo quảng cáo gần nhất  
**So that** tôi kiểm soát toàn bộ tình trạng vận hành trong suốt buổi demo và nhanh chóng nhận diện nếu có sự cố xảy ra  

---

## 2. Acceptance Criteria (Given-When-Then)

### AC1: [Happy Path — Hiển thị Dashboard vận hành đầy đủ thông tin]
- **Given** Người dùng đã kết nối Meta và đang ở tab "Dashboard"
- **When** Dashboard hiển thị
- **Then** Giao diện trình bày các khối thông tin trọng yếu:
  - Khối Kết nối: Huy hiệu "Đã kết nối Meta" (kèm nút Ngắt kết nối/Kết nối lại)
  - Khối Tài sản chọn: Tên & ID của Ad Account và Fanpage đang chọn
  - Khối Thống kê: Tổng số lượng chiến dịch đang có trên Ad Account
  - Khối Lịch sử chạy: Thẻ kết quả phiên tạo quảng cáo gần nhất lấy từ bảng `ad_creation_runs` (hiển thị trạng thái, thời gian chạy, và danh sách IDs: Campaign ID, Ad Set ID, Creative ID, Ad ID)

### AC2: [Edge Case — Chưa có phiên tạo quảng cáo nào trong lịch sử]
- **Given** Cơ sở dữ liệu SQLite mới khởi tạo hoặc bảng `ad_creation_runs` chưa có bản ghi nào
- **When** Người dùng xem phần "Kết quả tạo gần nhất" trên Dashboard
- **Then** Giao diện hiển thị trạng thái ban đầu: "Chưa có lượt tạo quảng cáo nào trong phiên này"
- **And** Hiển thị nút bấm dẫn tới tab "Tạo quảng cáo ngay"

### AC3: [UX & State Management — Loading State và Error Alert nhất quán]
- **Given** Người dùng thực hiện bất kỳ thao tác nào kích hoạt lời gọi API (kết nối, tải tài khoản, tạo quảng cáo)
- **When** Request đang được xử lý ở backend
- **Then** Nút bấm tương ứng hiển thị biểu tượng quay vòng (Loading spinner) và bị vô hiệu hóa (disabled) để ngăn chặn tương tác trùng lặp
- **When** Xảy ra lỗi từ phía backend hoặc Meta API
- **Then** Hệ thống hiển thị hộp thông báo lỗi màu đỏ nổi bật (Error Alert Banner) với nội dung giải thích an toàn và dễ hiểu, không làm sập (crash) giao diện

### AC4: [Backend Health Check — Tự động kiểm tra trạng thái dịch vụ]
- **Given** Ứng dụng frontend khởi động
- **When** Frontend thực hiện ping tới endpoint `GET /api/health` (hoặc `/api/v1/health`)
- **Then** Backend phản hồi HTTP 200 OK theo Consistent Envelope: `{"success": true, "statusCode": 200, "data": {"status": "healthy", "database": "connected"}}`
- **And** Nếu backend chưa chạy, frontend hiển thị thông báo: "Không thể kết nối tới Backend FastAPI. Vui lòng kiểm tra dịch vụ tại cổng 8000"

## 3. Architecture Guardrails for Coding Agents (BẮT BUỘC ĐỌC TRƯỚC KHI CODE)

> ⛔ **Cảnh báo cho AI Coding Agent**: Trước khi sinh hoặc sửa code cho User Story này, Agent BẮT BUỘC phải đọc và tuân thủ các tài liệu kiến trúc bất biến sau:

1. **Simplicity First Principle** ([AGENTS.md](../../../../AGENTS.md#2-core-philosophy-caution-over-speed)):
   - Tuyệt đối không thêm các biểu đồ phân tích chuyên sâu (Chart.js / Recharts phức tạp), không làm báo cáo Insights nhiều chiều làm chậm tiến độ 2 giờ.
   - Tập trung vào các card số liệu và bảng trạng thái tối giản.
2. **Consistent Response Envelope** ([08-integration-architecture.md](../../../architecture/08-integration-architecture.md)):
   - Định dạng response: `{"success": true, "data": {...}, "message": "..."}`.
3. **Data Model Guardrails** ([05-data-architecture.md](../../../architecture/05-data-architecture.md)):
   - Truy vấn lịch sử chạy từ bảng `ad_creation_runs` sắp xếp theo `created_at DESC LIMIT 1`.
