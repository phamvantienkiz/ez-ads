# User Story: US-006 — Chuỗi điều phối 5 lời gọi Meta Marketing API tạo tài nguyên

**Tầng tài liệu**: Implementation Layer  
**Release**: release-1 (MVP Demo)  
**Traceability**: Map to [FR-06] trong [prd.md](../../prd.md)  
**Priority**: P0 (Must)  
**Estimable Effort**: ~3 Story Points  

---

## 1. User Story Statement

**As a** Hệ thống Backend BAHA Ads Manager khi nhận yêu cầu tạo quảng cáo đã xác nhận  
**I want to** thực thi tuần tự chuỗi 5 lời gọi Meta Marketing API theo đúng trật tự phụ thuộc tài nguyên và lưu vết đầy đủ vào cơ sở dữ liệu SQLite  
**So that** các tài nguyên Image Hash, Campaign, Ad Set, Ad Creative và Ad được tạo thành công trên Meta và phản ánh trung thực kết quả về cho người dùng  

---

## 2. Acceptance Criteria (Given-When-Then)

### AC1: [Happy Path — Tạo thành công trọn vẹn 5 tài nguyên trên Meta]
- **Given** Yêu cầu tạo quảng cáo hợp lệ được gửi tới `POST /api/ads`
- **When** Backend tiến hành thực thi chuỗi API tuần tự:
  1. `POST /act_{id}/adimages` với `url={image_url}` $\rightarrow$ nhận về `image_hash`
  2. `POST /act_{id}/campaigns` với `objective=OUTCOME_TRAFFIC`, `status=PAUSED` $\rightarrow$ nhận về `campaign_id`
  3. `POST /act_{id}/adsets` với `daily_budget`, `optimization_goal=LINK_CLICKS`, `billing_event=IMPRESSIONS`, `targeting` VN 18-65 $\rightarrow$ nhận về `adset_id`
  4. `POST /act_{id}/adcreatives` với `object_story_spec` (gắn `page_id`, link, headline, `image_hash`, CTA `LEARN_MORE`) $\rightarrow$ nhận về `creative_id`
  5. `POST /act_{id}/ads` liên kết `adset_id` và `creative_id`, `status=PAUSED` $\rightarrow$ nhận về `ad_id`
- **Then** Backend lưu bản ghi vào bảng SQLite `ad_creation_runs` với `status = 'success'` và đầy đủ 4 IDs
- **And** Trả về HTTP 201 Created cho frontend kèm ID của từng tài nguyên thật

### AC2: [Negative Path — Lỗi tại bước tải/băm ảnh (Image Hash Failure)]
- **Given** URL hình ảnh người dùng cung cấp bị lỗi 404, không truy cập được công khai hoặc định dạng không được Meta hỗ trợ
- **When** Backend gọi `POST /act_{id}/adimages` và Meta trả về mã lỗi
- **Then** Backend dừng ngay tiến trình, không tiếp tục tạo Campaign hay Ad Set
- **And** Lưu bản ghi vào SQLite `ad_creation_runs` với `status = 'failed'`, ghi rõ `error_message` đã được làm sạch
- **And** Trả về mã lỗi cho frontend: "Không thể tải hình ảnh từ URL đã cung cấp. Vui lòng kiểm tra lại liên kết ảnh"

### AC3: [Negative Path — Thất bại một phần (Partial Failure Handling)]
- **Given** Bước tạo Campaign và Ad Set thành công (đã có `campaign_id` và `adset_id`), nhưng bước tạo Creative hoặc Ad thất bại (ví dụ: liên kết đích bị Meta chặn hoặc Fanpage thiếu quyền)
- **When** Meta trả về lỗi tại bước tạo Creative/Ad
- **Then** Backend dừng luồng, lưu bản ghi vào `ad_creation_runs` với `status = 'partial_failure'`, lưu lại các ID tài nguyên đã tạo thành công ở các bước trước
- **And** Frontend hiển thị rõ trạng thái: "Chiến dịch đã tạo một phần: Campaign ID ({id}) và Ad Set ID ({id}) đã được tạo, nhưng Mẫu quảng cáo gặp lỗi: {error_message}"
- **And** Tuyệt đối KHÔNG báo thành công toàn bộ, và KHÔNG tự ý retry tự động (để tránh tạo trùng tài nguyên gây tốn kém)

### AC4: [Security — Làm sạch dữ liệu nhạy cảm trong thông báo lỗi]
- **Given** Meta API trả về lỗi có chứa Access Token hoặc thông tin nhạy cảm trong payload chi tiết
- **When** Backend bắt Exception và trích xuất thông điệp lỗi
- **Then** Hệ thống loại bỏ hoàn toàn các chuỗi token, secret, và mã băm nhạy cảm trước khi lưu vào DB hoặc trả về cho frontend
- **And** Thông điệp trả về chỉ bao gồm mã lỗi nghiệp vụ của Meta và giải thích an toàn

### AC5: [Concurrency & Idempotency — Khóa chống gửi yêu cầu trùng lặp (Double-submit)]
- **Given** Một request tạo quảng cáo đang được xử lý ở backend
- **When** Người dùng hoặc script cố tình gửi thêm một request khác cùng lúc
- **Then** Nút bấm submit ở frontend bị khóa (disabled + spinner) và backend kiểm soát không để xảy ra race condition tạo trùng chiến dịch

## 3. Architecture Guardrails for Coding Agents (BẮT BUỘC ĐỌC TRƯỚC KHI CODE)

> ⛔ **Cảnh báo cho AI Coding Agent**: Trước khi sinh hoặc sửa code cho User Story này, Agent BẮT BUỘC phải đọc và tuân thủ các tài liệu kiến trúc bất biến sau:

1. **Data Model Guardrails** ([05-data-architecture.md](../../../architecture/05-data-architecture.md)):
   - Bảng ghi lịch sử: `ad_creation_runs` (các cột: `id`, `ad_account_id`, `page_id`, `campaign_id`, `adset_id`, `creative_id`, `ad_id`, `status`, `request_summary`, `error_message`, `created_at`).
   - Các cột ID phải là `nullable` để hỗ trợ lưu vết khi gặp lỗi Partial Failure.
2. **API Payload Invariants** ([08-integration-architecture.md](../../../architecture/08-integration-architecture.md)):
   - Phiên bản Meta API: `v20.0`.
   - Mọi request tạo tài nguyên bắt buộc phải truyền `status: "PAUSED"`.
   - Endpoint backend: `POST /api/ads`.
3. **No Automatic Retry Rule**:
   - Nghiêm cấm đặt cơ chế `tenacity` hoặc vòng lặp retry tự động cho các thao tác `POST` tạo tài nguyên trên Meta. Khi lỗi phải báo ngay cho người dùng.
