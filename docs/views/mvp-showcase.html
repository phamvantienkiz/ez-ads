6 Quyết định Kỹ thuật (Design Decisions D-01 → D-06) đã làm rõ trước khi viết code

Mã Vấn đề ban đầu chưa rõ Quyết định Chốt cho MVP (Grounded Specification) Tác động bảo vệ dự án
D-01 Phiên bản API & Tham số Tạo Ads Cố định Meta Graph API v20.0, mục tiêu OUTCOME_TRAFFIC, tối ưu hóa LINK_CLICKS, đấu thầu tự động LOWEST_COST_WITHOUT_CAP. Loại bỏ lỗi tương thích giữa các phiên bản Marketing API cũ/mới.
D-02 Đơn vị Tiền tệ Ngân sách (Budget) Tự động nhận diện currency của Ad Account: Giữ nguyên số nguyên cho tiền tệ 0 thập phân (VND, JPY, KRW) và nhân 100 cho tiền tệ có cent (USD). Ngăn chặn rủi ro đội ngân sách lên gấp 100 lần hoặc bị Meta từ chối.
D-03 Cơ chế Upload Hình ảnh Sử dụng Public Image URL gửi qua POST /act_{id}/adimages để lấy image_hash thay vì multipart binary phức tạp. Giúp luồng Preview và Backend nhẹ, dễ kiểm thử trong 2 giờ.
D-04 Xử lý Lỗi giữa chừng (Partial Failure) Không rollback xóa tài nguyên trên Meta; ghi nhận chính xác các ID đã tạo vào SQLite (status=partial_failure) và trả về failedStep. Minh bạch tuyệt đối về trạng thái thực tế trên Meta Ads Manager.
D-05 Quản lý Phiên & Chống Double-Submit Single-user session (meta_sessions id=1) + Khóa đồng thời asyncio.Lock trả về HTTP 409 Conflict nếu bấm liên tiếp. Đảm bảo không bao giờ tạo trùng 2 chiến dịch khi mạng chậm.
D-06 Ngôn ngữ Thiết kế Giao diện Áp dụng hệ thống "Soft Clean Cards": Nền sáng #F3F3F5, Card trắng bo góc 28px, nút hành động chính màu --ink (#111114). Giao diện hiện đại, rõ ràng, tạo độ tin cậy cao khi trình diễn.

Slide 04 · Real-World Problem Solving

Giải Bài Toán Kết Nối Thực Tế Trên Tài Khoản BAHA

Phân tích nguyên nhân và cách xử lý linh hoạt khi tích hợp với tài khoản Meta của khách hàng trong điều kiện không được cấp mật khẩu cá nhân để mở khóa META_APP_SECRET.

Problem Solved
Rào cản thực tế phát sinh

Vì sao luồng OAuth mặc định bị chặn khi Demo?

  • 1 Lỗi "ID ứng dụng không hợp lệ": File .env ban đầu chứa giá trị mẫu (test_meta_app_id), cần thay bằng dãy số Meta App ID thật trên tài khoản BAHA.
  • 2 Không thể lấy META_APP_SECRET: Trên developers.facebook.com, nút "Hiển thị" khóa bảo mật luôn yêu cầu nhập lại mật khẩu Facebook của chủ tài khoản BAHA.
  • 3 Rủi ro cấu hình Redirect URI: Ứng dụng Meta mới tạo chưa bật sẵn sản phẩm Facebook Login hoặc chưa khai báo localhost:8000.
Giải pháp Kỹ thuật đã Triển khai

Kiến trúc Xác thực Đa Chế Độ (Dual-Mode Auth)

  • ✓ Nâng cấp Backend MetaAuthService: Hỗ trợ đồng thời Authorization Code Flow, Implicit Flow (response_type=token) và endpoint POST /api/v1/meta/token-callback.
  • ✓ Cải tiến UI ConnectCard.tsx: Cho phép nhập trực tiếp Meta App ID và nạp nhanh Access Token từ Graph API Explorer ngay trên màn hình Dashboard.
  • ✓ Kết quả thực tế: Đã kết nối thành công vào phiên SQLite (Connected), xác thực với Meta Graph API và tải được toàn bộ thông tin tài khoản của BAHA.

Ma trận 3 Chế độ Kết nối đã được hỗ trợ sẵn trong BAHA Ads Manager

Chế độ kết nối Thông tin cần có Trạng thái trong Codebase Đánh giá tính phù hợp
1. OAuth Code Flow (response_type=code) META_APP_ID + META_APP_SECRET Đã cài đặt & Pass Test Chuẩn mực cho môi trường Production khi doanh nghiệp bàn giao đủ khóa bí mật.
2. OAuth Implicit Flow (response_type=token) Chỉ cần META_APP_ID + Redirect URI Đã cài đặt HTML Bridge Phù hợp khi cấu hình được Facebook Login Settings nhưng không có mật khẩu mở App Secret.
3. Graph Explorer Token Bridge (Đang dùng cho Demo) Meta App ID + Token từ tools/explorer Đã kết nối Live thành công Tối ưu nhất cho buổi Demo 2 giờ: Nhanh, an toàn, lấy ngay dữ liệu thật mà không cần mật khẩu.
